## Headline findings

### 1. Reconnaissance value flips sign with task difficulty (Fig 3 winner)

`fig3a_recon_lift_by_difficulty.{pdf,png}` — On (UT, IJ) pairs where the
no-knowledge attacker already had **≤5%** ASR, adding a single best
knowledge asset lifts ASR by **+29.7pp** on average (n=629 pairs, 4 suites).
On pairs where no-knowledge already worked **≥95%** of the time, adding
that same recon asset *lowers* ASR by **-15.6pp**. Spearman
ρ(base ASR, recon lift) = −0.317, p = 4e-16.

Interpretation: recon doesn't just unlock new attack surface — it can
break attacks that would have worked on their own. The "robust"
column averages a +29.7pp gain. The "already broken" column shows that
elaborate, reconnoitered payloads can over-engineer their way into
refusals on tasks where a naive attacker would have succeeded.

This replaces the blank Figure 3 ("Categorizing the user tasks by
attacker freedom") in the current draft. The empirical bucketing
(by no-knowledge ASR) is concrete and defensible, unlike the original
subjective "attacker freedom" label.

### 2. The `spotlighting_with_delimiting` defense backfires on adaptive attacks

`aux9_spotlighting_backfire.{pdf,png}` — For Cobra-Full, AgentDojo's
own spotlighting defense **raises** ASR in all four suites:

| suite     | no defense | repeat_user_prompt | spotlighting |
|-----------|------------|--------------------|--------------|
| banking   | 0.42       | 0.23               | **0.65**     |
| slack     | 0.59       | 0.50               | **0.88**     |
| travel    | 0.33       | 0.20               | **0.38**     |
| workspace | 0.57       | 0.21               | **0.60**     |

Suite-averaged ΔASR vs no-defense: **+14.9pp** for spotlighting,
−19.4pp for repeat-user-prompt. The same spotlighting defense
neither helps nor hurts the static baselines (ChatInject −1.9pp,
IgnorePrev −1.2pp).

Mechanism (hypothesis to verify in transcripts): the delimiter
tokens that "spotlight" the untrusted region give the adaptive
attacker an unambiguous structural anchor to write into.

### 3. The recon ROI saturates fast

`fig3b_asset_hierarchy_roi.{pdf,png}` — `agent_task` and
`tool_names_and_parameters` together reach ≥90% of the full-recon ASR
ceiling on every suite. Minimum-viable recon for the paper's threat
model is small.

### 4. Multi-asset recon is super-additive (banking only)

`fig3d_super_additivity.{pdf,png}` — On banking under `repeat_user_prompt`,
the `behavioral_rules + tool_names_and_parameters` combo reaches ASR=0.25
vs the independence-prediction of 0.15 (synergy = **+10pp**).
The `filters + guardrails + structural_defenses` combo: observed 0.16 vs
predicted 0.06 (synergy = **+11pp**).

Limited to banking because it's the only suite with the multi-asset
ablation cells. Worth flagging as a publishable single-suite result.

## Numeric discrepancies vs paper draft

The replicated Table II shows Cobra-Full at **55.2%** suite-averaged ASR
on gpt-4.1 (no defense). The current paper draft Table II reports 86.0%.
Likely cause: the paper's number is the final-framework iteration (Cobra
V4 or a not-yet-committed V5), not the aggregate across V1–V4. The
parquet rolls everything labeled "cobra_full" together for the cross-
baseline plot. To reproduce the 86.0%, filter `per_attempt.parquet` to
`framework == 'cobra_v4' and cobra_variant.isna()` once that data is
populated (currently V4 has only 9 rows on disk).

All ASR-Knowledge cells reproduce their `summary.asr` value within 0.005.
The unified ingest passes the sanity checks documented at the end of
`build_parquet.py`.

## Caveats and non-goals

- No new SWE-Bench / OpenHands analysis (paper Table IV is untouched).
- No new attack runs, no new defense designs.
- `aux6_failure_taxonomy` uses Cobra's own evaluator labels rather than
  an LLM-judged scheme. Adding LLM-judged labels for ASR-Knowledge
  transcripts is a stretch goal.
- `aux7_cost_pareto` uses `payload_len` (canonical) since `duration_s`
  cross-framework normalization is noisy.
- The "recon hurts already-broken tasks" finding (-15.6pp) is driven by
  asset_set=`benign_response` and `behavioral_rules` cells where the
  attacker over-engineers the payload. Spot-checking these transcripts
  before publication is worthwhile.
- AgentVigil is scored on the May-12-2026 retrain run's **held-out test
  split only** (487 cases, ASR 46.0%), not the 121-case fuzzing split the
  MCTS trained its templates on. The no-defense test-set per-case file was
  not retained, so `ingest_agentvigil()` reconstructs per-suite counts
  exactly as `combined_results.json` minus `fuzzing_results.json` and emits
  one synthetic row per case (every figure aggregates AgentVigil by suite).
  AgentVigil under defenses is out of scope — it appears only in the
  no-defense column of `aux2`/Table III.
